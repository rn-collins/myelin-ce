Privacy by architecture.

Myelin requires no account, identity, email, analytics cookie, form submission, or server-side learner record.

Course data

Courses store lesson flags, written scenario exercises, quiz attempts, completion time, score, and a random record ID in this browser’s local storage. AI-7 uses myelin-ai7-v2; advanced courses use course-specific version-2 keys.

Dashboard and tools

The dashboard reads those local course keys to show progress. Field-tool entries use myelin-field-tools-v1. No course, dashboard, brief, or tool sends learner content to Myelin.

Your controls

Course records, the full learning portfolio, and field-tool records can be exported as JSON to your device. Course, tool, and portfolio deletion controls remove the corresponding local data.

What “stays in your browser” actually means

This site keeps your progress in Web Storage (localStorage). Four properties of that mechanism are worth knowing before you rely on it, because they decide whether your work survives.

  • It is tied to this origin. Storage is scoped to the document's origin, so what Myelin writes is readable only by Myelin — and Myelin's own server never receives it, because nothing here transmits it.
  • It has no expiry. Unlike a session store, localStorage has no expiration time and survives closing the tab, quitting the browser, and restarting the machine.
  • It is per-browser and per-device. Progress recorded in Chrome on your laptop is not visible in Safari, on your phone, or in another profile. There is no account to sync it, which is the trade you are making for not having one.
  • Private browsing discards it. Data written by a page loaded in a private or incognito session is cleared when the last private tab closes. If you work through a course in a private window, expect to lose it.

One more: if you have configured your browser to block sites from storing data, the write simply fails. The pages are built to keep working in that case — every lesson, brief, and question is in the HTML — but nothing will be remembered between visits.

How to keep your work

Because there is no account, there is no password reset and no support desk that can recover anything. If a record matters to you, take it off the browser:

  1. Export it. Every course exports a JSON record, the dashboard exports the whole portfolio, and the field tools export their entries. Those files are yours and are written to your device.
  2. Print or save the record as a PDF. The record sections are laid out for printing.
  3. Do it before clearing site data. “Clear browsing data”, a browser reset, or a new device wipes progress with no warning from us, because we do not know it happened.

AI-7 also accepts an exported progress file back via Import progress, which is the only supported way to move a course between browsers or devices.

What commonly goes wrong

The failure we would expect is someone completing a course on a work machine, having site data cleared by policy overnight, and returning to an empty page. The material is unchanged and can be re-read in an afternoon; the record is gone. Export at the point you finish, not at the point you need it.

The second is entering real information into a scenario box. The note fields and tool fields are text boxes, so they will accept anything — but they exist to build an exercise, not a case file. Use synthetic or appropriately minimized descriptions, as the note below repeats.

Do not enter

Scenario notes and tool fields accept text only to create local exercises. Do not enter client, patient, student, privileged, health, proprietary, or confidential information. Use synthetic or appropriately minimized descriptions.
